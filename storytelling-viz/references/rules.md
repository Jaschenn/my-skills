# 规则的原因与反例

SKILL.md 写"做什么",这里只写"为什么"和"踩过的坑"。新增规则时:规则本身写进 SKILL.md,原因/反例写在这里,并同步 CHANGELOG。编号仅供引用,不必和 SKILL.md 一一对应。

## 数据口径
- **R0 当期未完结**:9 月只到 9/15 却和 8 月整月比,会"凭空"跌一半。→ 剔除、折算,或标"截至 X 日"并视觉区分。
- **R0b 小分母**:分母 30 人的通过率从 40% 到 50%,只是多了 3 个人。→ 在标注或脚注里给出样本量,别据此下结论。

## 图的文字
- **R1 标题 = 结论,数字由数据算**:手写数字在数据更新后不会跟着变,标题和图会对不上。
- **R2 一面板一论点**:两个论点挤进一个面板,读者只会记住更显眼的那个。


## 选图
- **R6 占比变化不要用绝对值堆积柱**:中间段没有共同基线,肉眼比不出占比变化。
- **R7 小变化要标 pp**:几个 pp 的变化在 0–70% 的轴上是一条平线。
- **R8 柱子都标了数 → 删 y 轴和网格**:两套刻度互相干扰。
- **R9 增速和规模同时要说**:条长编码一个、标签写另一个;只给增速会让小渠道看起来最重要(如刚上线的小品类)。

## 视觉
- **R10 焦点色 ≠ 好坏色**:用红色高亮"重点渠道",读者会以为它出了问题。
- **R11 强调不只靠颜色**:整套图都是"灰 + 一根红"会有模板感,而且第二页起读者就对这种强调麻木了。
- **R12 A 对比 B 不压灰**:地位相当的两方,一方压成灰就等于预设了结论。
- **R13 文字对比度 ≥ 4.5:1**:浅灰线条可以,浅灰文字投影时读不出。MUTED (#6b7280) 在白底约 4.8:1,是文字能用的最浅色。
- **R13b 红绿不能是唯一信号**:约 8% 的男性有红绿色弱;好坏必须同时用符号、箭头或文字表达。
- **R15 直接标注代替图例**:图例让读者在图和图例之间来回对照;字段名(channel、metric)对读者没有意义。
- **R16 面板 plot_margin=0、左缘对齐**:各面板标题错开几毫米就会显得不整齐。
- **R17 轴范围只留标注所需空间**:多出来的空白会把数据挤成一条线。
- **R18 categorical ≤ 5 类**:超过 5 种颜色就分不清了;超出时 `PAL.categorical` 直接报错,逼你合并成"其他"或改成排名图。

## 中文排版
- **R19 zh()**:半角逗号、冒号混在中文里,在投影上非常显眼。坑:旧版会把网址里的 `:` 改坏,也会在全角标点后留下空格,v1.1 已修复。
- **R20 wrap_cjk 禁则**:行首出现标点、`17.5%` 被拆成 `17.` 和 `5%` 两行,都是一眼可见的排版错误。
- **R21 中英文间空格全页一致**:混用比统一不加更难看。

## 经营分析(house style)
- **B1 涨跌不用红绿**:中外习惯相反(A 股红涨,国际绿涨),业务含义又和方向无关(退货率上升是坏事)。用 ▲▼ 和中性色表达方向,红色只留给"异常",读者看到红就知道要处理。
- **B2 异常的三把尺子**:落后时间进度(目标类)、超过固定阈值(运营约定)、超出历史 ±2σ(自身波动)。只用固定阈值会让波动大的指标天天报警、波动小的指标出了问题也不报。
- **B3 同期按星期对齐**:交易类日度数据有很强的周内规律,"10/5 周日 vs 9/5 周五"会把周末效应当成变化;累计值和账单日/到期日相关的指标才按日历日对齐。
- **B4 未完结期**:当月只过了 9 天,直接画在月度柱/线上会像"暴跌"。虚线 + "截至 X 日" + 按进度折算的预估,读者既看到实际也看到走向。
- **B5 双轴只留一种**:规模柱 + 比率线是经营汇报的常用组合;其余双轴(两个金额、两条线)会让交叉点被误读。比率轴从 0 开始或固定范围,避免自动缩放把 0.5pp 的波动放大成"剧烈变化"。
- **B6 口径脚注必填**:经营汇报里最常被挑的问题是口径不清、和其他报表对不上、格式不统一、看不出重点。前两条只能靠脚注写清分子分母、币种、时间窗口和对比基准。
- **B7 拆解树的贡献**:乘法拆解用对数份额(各因子贡献之和 = 100%);加法拆解在子项互相抵消时份额会出现 333% 这类数字,改为直接写变化量。

## 工程
- **R22 按最终尺寸渲染再拼装**:先画大图再缩小,字号会变成 6–8pt,投影看不清;期刊图更是如此(7pt 字在缩放后不合规)。
- **R23 输出格式跟着用途走**:slide → 轮廓 SVG + 可编辑 SVG + PNG;文档/期刊 → PDF(Type 42 嵌入字体,期刊拒收 Type 3)+ SVG + 高 dpi PNG。
- **R23b 拼接 SVG 时给 id 加前缀**:每个面板都是独立的 matplotlib SVG,字形和 clipPath 的 id 会重复(实测两个面板就重复 48 个),Figma/Illustrator 导入可能错乱。
- **R24 字体**:Linux 上 matplotlib 只注册 .ttc 字体集的第一个字面,`Noto Sans CJK` 常以 `Noto Sans CJK JP` 出现。中文用 CJK 字体;英文图用拉丁字体(Inter/Helvetica/Arial),含中文的标签自动回退到 CJK 字体。
- **R25 布局由数据和尺寸算,不手写坐标**:旧示例里 `limits=(33, 68)`、`x=-0.19` 这类为构造数据调好的数,一换真实数据(长标签、负值、30 个类别、离群值)就溢出或重叠。图表函数在知道面板尺寸后,按文字实际宽度换算留白(Frame)。
- **R26 渲染后自动 QA**:人眼看缩略图发现不了 1–2 个字的重叠或裁切;`figure()` 每次渲染都检查文字重叠、越界、被绘图区裁切,并检查文字对比度。QA 有警告就不算完成。
- **R26b 检查必须和渲染用同一套度量**:matplotlib 3.11 改了文字排版(默认行距 "normal",文字框用字体完整行高),旧的按 "lp" 字形高度算的文字面板比 matplotlib 报告的框矮约 3px,于是每张带标题/脚注的图都报"超出面板"——检查失去意义，还会让人一直去改没问题的图。现在 `vmetrics` 直接量 matplotlib 的文字框(与 plotnine 一样用数字行距 1.2),字宽在 720dpi 下量(72dpi 会按整点取整，多段富文本拼接时会吃掉空格)。
- **R27 边界用例回归测试**:每次改图表函数都跑 `references/tests/edge_cases.py`(长标签、40 个类别、负值、缺失、单点、离群值、5000 点、13 个分面、中英混排),在 slide 和期刊两种规格下都要符合预期。
